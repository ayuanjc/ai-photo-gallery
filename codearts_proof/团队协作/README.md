## 三、并行开发的工程约束（可直接作为答辩素材）

组员 A 的提示词里明确写入了多分支协作约束，这是本项目能在 9 天内并行推进 9 个功能分支的关键：

> 本项目有多个功能分支同时在开发，你只负责本模块。
> 1. 只允许修改下面「允许修改的文件」清单里的文件
> 2. 新增配置项统一加在 app/core/config.py 的 Settings 类末尾
> 3. 开发前先 git checkout main && git pull origin main
> 4. 若 git pull 后 config.py 有冲突，先 git rebase main 再继续
> 5. 不动其他模块文件

配套的做法是给每个 Agent 一份**文件白名单**，把冲突面从「整仓合并」压缩到
「config.py 末尾追加」，从而让三条分支可以同时向 main 合入。
