## 3. 三个代表性 Prompt 及效果

### ① 混沌工程测试（防御性编程）

> 「你现在是一位拥有 10 年经验的资深测试开发工程师，擅长『防御性编程』和『混沌工程』。你的任务是想尽一切办法搞崩我的代码，找出潜在的死锁、未捕获异常、错误降级和数据解析错误。」

**效果**：生成 `brute_test.py` 六大类破坏性测试，首轮 154 通过 / 6 失败，暴露 **5 个真实漏洞**（P0×2 / P1×1 / P2×2），全部修复后 250 测试全绿。人工写测试很难主动想到「搞崩自己」的攻击视角。

### ② 严格代码审查

> 「你是一个极其严格的资深 Python 后端开发工程师…找出所有 Bug、逻辑错误、性能隐患和安全漏洞。不要说客套话，不要提炼亮点，直接指出问题。」

**效果**：三轮审查共修复 **36 项**（第一轮 16 项：P0 安全 5 / P1 可靠性 4 / P2 加固 7；第三轮 2 高危 + 6 中危 + 7 低危），测试从 230 条一路增长到 1,085 条全绿。对比经验：不带「不要客套话」约束的审查输出亮点占一半篇幅，有效发现密度明显更低。

### ③ 现场级任务书（演示站）

> 「重做『云影图鉴·语义检索』演示站纯前端单文件…后端契约字段一个不能改…禁止假状态、禁止 score 换算百分比…」（完整任务书约 4,000 字，见提示词库第 143 轮前后的长任务）

**效果**：单文件 `index.html` 8.8 KB（内联 CSS/JS、零外链断网可用），一次通过 mock 契约 9 项验证 + 静态审查 33 项，与旧版 10 条差异全部可追溯。

## 5. 诚实分工

**码道完成的**：绝大多数代码编写（51 端点、前端页面、测试用例从 197 → 1,085 条）、代码审查初筛、破坏性测试设计、bug 定位与修复建议、文档草稿（Swagger 汉化、部署文档）、演示站全量实现。

**人工决策的**：技术选型（FastAPI / CLIP / Immich 集成形态）、架构分层与模块边界、指标口径（坚持 score 展示真实余弦、拒绝换算百分比）、演示素材筛选（487 张样例的人工定向挑选）、写回闸门等安全规则、上线运维（部署、回滚、备份）、所有最终代码评审与合并（人工把关于 git 提交与 MR 的最终决定权）。

一句话：**架构与口径由人定，实现与验证由码道干，合并与上线由人拍板。**
