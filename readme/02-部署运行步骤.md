## 5. 完整版（接 Immich）启动

```bash
# 适用：Debian 12 / Ubuntu 22.04
apt-get install -y redis-server && systemctl enable --now redis-server
python3 -m venv venv && venv/bin/pip install -r requirements.txt
cp .env.example .env && vim .env     # 填 IMMICH_BASE_URL / IMMICH_API_KEY
venv/bin/python -m pytest tests/ -q  # 预期：1085 passed（退出码 0）
venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
# 预期启动日志：INFO: Uvicorn running on http://127.0.0.1:8000
curl -s http://127.0.0.1:8000/api/v1/health
```

## 6. 常见故障 6 条（全部来自真实排错记录）

### ① onnxruntime 版本不匹配（prepacked 张量报错）

- 现象：启动或首次搜索报 `Deserialize tensor failed` / `Exception during loading: 'tensor' with ... external data`
- 原因：文本塔 ONNX 是 prepacked 外部数据格式，`onnxruntime ≤ 1.20` 读不了
- 修复：

```bash
# 适用：Debian 12 / Ubuntu 22.04
$APP_DIR/venv/bin/pip install "onnxruntime==1.31.0"
systemctl restart yunying-demo
```

### ② 端口占用（8100 或 80）

- 现象：`Address already in use` / nginx 起不来
- 定位与修复：

```bash
ss -lntp | grep -E ':8100|:80 '    # 找到占用进程
systemctl stop <占用服务> || kill <PID>
systemctl restart yunying-demo && nginx -t && systemctl reload nginx
```

### ③ nginx 502（/api/ 反代失败）

- 现象：静态页能开，搜索一直 502
- 定位：`systemctl status yunying-demo`（多为 uvicorn 没起或起在别的端口）
- 修复：

```bash
journalctl -u yunying-demo -n 30 --no-pager   # 看真实报错（常见为④/⑤）
systemctl restart yunying-demo
curl -s http://127.0.0.1:8100/api/health      # 先确认后端直连 OK，再看 nginx
```

### ④ 模型路径错误

- 现象：`FileNotFoundError: model.onnx` 或 `tokenizer.json`
- 修复：确认三件套都在 `$APP_DIR/models/` 且非空（`install.sh` 第 5 步会拦截）；改路径后 `systemctl restart yunying-demo`

### ⑤ Redis 未启动（完整版）

- 现象：启动日志 `Connection refused`，缓存全部退化为进程内缓存（功能可用但性能下降）
- 修复：`systemctl enable --now redis-server && systemctl restart <本项目服务>`

### ⑥ Immich 不可达（完整版）

- 现象：`httpx.ConnectError` / 超时；管理台显示 Immich 探针失败
- 定位：`curl -s $IMMICH_BASE_URL/api/server/ping -H "x-api-key: <KEY>"`（预期 `Pong`）
- 修复：核对 `.env` 的 `IMMICH_BASE_URL`（Docker 部署注意映射端口 2283/3200）与 API Key；网络通了再重启服务

> 附赠第 ⑦ 条（真实踩坑）：uvicorn 启动报 `ImportError: ... sentinel` —— 先 `venv/bin/pip install -U typing_extensions anyio` 再重启，依赖版本错位所致。

## 7. 回滚与卸载

```bash

rm /etc/nginx/sites-enabled/yunying && nginx -t && systemctl reload nginx
# 数据与代码保留在 /opt/yunying，确认不再需要后手动删除
```
