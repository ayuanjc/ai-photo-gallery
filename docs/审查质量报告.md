## 二、三个值得写进 PPT 的发现

### 1. 公网无凭证可读写评分库（第五轮 R5-1，Blocker）

`app/api/routes/ratings.py` 的 6 个端点此前只有业务校验、没有 `verify_api_key` 与 `rate_limit_guard`。评分数据是整条检索链路的排序输入，等于**任何人都能改写 AI 的排序偏好**。修复后 6 个端点全部挂鉴权 + 限流，并补了 401 矩阵测试（17 个用例里的一大半）。

### 2. 写回闸门可被请求体旁路（第四轮 F1，高危）

原实现有一条路径：调用方在 payload 里塞 `scene` dict，服务端直接采信并写回 Immich。现在删掉这条采信路径，`SceneAnalyzer.analyze` 增加 `trusted` 参数——**webhook 无 token 时产出 `source=tag_inferred`，不可写回、不写缓存**（防投毒），`source` 由服务端写入而不是调用方声明。

### 3. 设置接口可把 API Key 外送（第四轮 F2，高危）

`settings` 写 `.env` 此前只要有 admin 身份就放行；这意味着改掉 `immich_base_url` 就能让服务带着 `IMMICH_API_KEY` 请求任意主机。修复：**未配置 `ADMIN_API_KEY` 时任何环境直接拒绝**，硬闸。

另外还有：SSRF 校验阻塞事件循环（F3，改同步快段 + 异步补 DNS）、feedback 限流字典可被随机 id 打爆内存（F4，容量上限 1 万）、demo 前端 5 处未转义导致 XSS（F8）——细节见 commit message。

## 三、部署链路与交付物修复（不是代码也能扣分）

| 项 | 原缺陷 | 后果 |
|---|---|---|
| R5D-2 | `deploy.sh` 用 `enable` 而非 `enable --now` | 更新不生效，评审看到的是旧版本 |
| R5D-3 | `install.sh` 回滚 trap 用 `ERR` | `exit 1` 不触发，回滚失效 |
| R5D-4 | 自检 `curl` 无 `-f` | 502 也判成功 |
| R5D-5 | systemd unit 无 `User=www-data`、无沙箱加固 | 服务以 root 跑 |
| R5D-6 | nginx 无 `server_tokens off`、无安全头 | 暴露版本号 |
| R5D-7 | CLIP 模型路径两处不一致 | 部署后启动失败 |
| R5D-1 | `readme/01` 内嵌的 install.sh 副本是旧版 | 评审照抄必失败 |
| R5T-2 | 证据包路径含 `C:/Users/...` | 个人目录泄漏进提交物 |
| R5T-1 | `.env.example` 写回开关写成 true（注释说默认关） | 评审一启动就写库 |

→ 这几条对应的都是「文档写得对、代码跑不对」的经典塌陷，外部审查一次全捞出来了。

## 四、答辩怎么用（三句话）

1. **不要说「我们代码没 bug」**。说：「我们请外部 AI 对 134 个文件做了五轮防御性审查，最近两轮报出的 1 个 Blocker + 2 个高危全部当天修复，回归用例从 1,098 涨到 1,115，全绿。」
2. **Blocker 要主动讲**。评分库无鉴权这件事，评委一看 `ratings.py` 的装饰器就知道有没有——主动说出来是加分，被问出来是减分。
3. **强调「审查方是外部」**。同一套代码让另一家模型读，才能证明不是自己糊自己；这也是「AI 辅助研发」的真实工作流，不是包装。
