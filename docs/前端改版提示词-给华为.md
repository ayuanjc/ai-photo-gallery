## 2. 后端契约（原文，字段名一个都不能改）

### GET /api/health
```
{"status":"ok","model":"ViT-B-32__openai","count":487,"dim":512,"load_ms":374.2}
```

### POST /api/search
请求体：
```
{"query":"海边日落","top_k":24}
```
- query：必填，1–200 字符
- top_k：1–200，默认 24
- scene：可选，传了只返回该场景 key 的结果（一般不用）

响应体（真实样本，已裁短）：
```
{"query":"海边日落",
 "translated":"a photo of the sunset at the beach",
 "translated_used":true,
 "text_cached":true,
 "top_k":3,
 "results":[{"id":"74f00ea7-bf40-49ad-9f4f-8c05157727a4","score":0.2917,"rel":1.0,
   "thumb":"/thumbs/74f00ea7-bf40-49ad-9f4f-8c05157727a4.webp","w":321,"h":480,
   "takenAt":"2025-11-09T09:05:31.000Z","fileName":"A0107979.ARW","city":null,"country":null,
   "scene":null,"sub":"单人","scene_sim":0.27}],
 "timing_ms":{"translate":0.38,"text_embed":0.0,"total":0.6}}
```

字段含义（务必照做）：
| 字段 | 含义 | 前端怎么用 |
|---|---|---|
| score | 真实余弦相似度，0–1，通常落在 0.20–0.35 | 原样显示三位小数，禁止换算成「匹配度 92%」 |
| rel | 相对 top1 的比值，top1 = 1.0 | 作为横向条形宽度 rel*100% |
| translated | 中文被改写成的英文短语 | 必须显式展示给用户 |
| translated_used | 是否发生了改写 | true 时标注「中文已改写」 |
| text_cached | 文本向量是否命中缓存 | true 时标注「命中缓存」并说明此时耗时≈0 |
| timing_ms.text_embed | 文本编码耗时 ms | 显示「编码 xx ms」 |
| timing_ms.total | 服务端全流程 ms | 显示「全流程 xx ms」 |
| scene / sub | 预计算场景标签，可能为 null | null 不显示，有值显示为小 chip |
| city / fileName | 可能为 null | city 为 null 时显示 fileName 前 20 字 + takenAt 日期 |
| w / h | 缩略图尺寸 | 必须写进 img 的 width/height，防布局抖动 |

### GET /api/scenes
返回 {"scenes":[{"key":"lake","label":"lake","count":34}, ...]}。注意 label 目前是英文 key，前端若要用请自带中文映射表，不要直接展示英文。

### 错误
- query 为空或超 200 字符 → HTTP 422（前端先校验，不要让它发生）
- 后端重启中 → 502 或连接失败，必须给「重试」

## 3. 硬约束（逐条验收）
1. 不改 API、不改 nginx、不加后端依赖
2. 不引任何外网资源：无 Google Fonts、无 CDN、无外链图片、无在线图标库、无外部统计脚本。评审现场可能断外网，断网后页面必须仍然完整可用
3. 纯静态产物；可用原生 ES module，也可用 vite 打包交付 dist，但最终必须直接躺在 /opt/yunying/web/ 被 nginx 静态发出去（nginx 配了 try_files $uri $uri/ /index.html，SPA 路由 OK）
4. 体积预算：首屏（HTML + 首屏 CSS/JS + 前 8 张缩略图）≤ 220KB；CSS+JS 未压缩合计 ≤ 80KB
5. 优先单文件 index.html，便于一把替换；若必须拆，最多 6 个文件（index.html / app.css / app.js / 内联 SVG）
6. 兼容 Chrome/Edge 最近两个大版本与 iOS Safari 16+，不用 IE 特性
7. 只允许 sessionStorage 存「最近搜索」，不用 localStorage（演示机多人共用）
8. 时间按 Asia/Shanghai 显示，格式 2025-11-09
9. 文案全简体中文、专业克制、不用网络梗
10. 禁止假状态：不许「AI 正在思考」「生成中 60%」这类编造进度，所有数字必须来自真实响应

## 4. 视觉方向（别做成营销落地页）
风格：深色专业工具感，参考 Linear / Raycast 的克制，不是 SaaS 卖课页。
- 色板：--bg #0A0E13、--surface #111820、--surface2 #0E141B、--line #1E2833、--line-strong #31465C、--fg #E8EEF4、--dim #8A97A4、--accent #4EA8FF、--ok #3DDC97、--warn #F5A623
- 字体栈：-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif；分数与耗时用 ui-monospace, Consolas
- 字号阶梯 12 / 13 / 15 / 17 / 21 / 28；标题行高 1.2，正文 1.6
- 间距一律 8 的倍数：8 / 12 / 16 / 24 / 32 / 48；圆角 8（卡片 10，chip 999）
- 动效不超过 180ms ease-out，只动 opacity / transform；必须尊重 prefers-reduced-motion: reduce
- 焦点必须可见：:focus-visible 用 2px accent 外框，任何地方不许 outline:none 了事

## 5. 页面结构（按顺序实现）

### S1 Hero（高度不超过 200px，不要占满屏）
主标题：云影图鉴 · 语义检索；右侧一枚小标签：CLIP ViT-B-32 · onnxruntime CPU。
两行说明（原文照抄，不要改口径）：
> 用一句中文描述去检索照片。查询在本机改写成 CLIP 能读的英文短语、编码成 512 维向量，与每张图的向量算余弦相似度排序。不调用任何外部 API，也不编造分数。
一行事实条（数字必须取自 /api/health）：样例库 <count> 张 ｜ 向量维度 512 ｜ 文本编码 <n> ms ｜ 打分口径 真实余弦 / 相对 top1 百分比

### S2 搜索区（sticky top，吸顶 + 背景模糊 + 底边线）
单行：大输入框（placeholder：试试：海边日落 / 城市夜景 / 火锅 / 蓝色的车）+ 主按钮「搜索」。
输入框内右侧提示：按 / 聚焦 · Enter 搜索（移动端隐藏）。

### S3 示例查询（紧跟搜索区，一行 chips，可横向滚动）
12 个词：海边日落、城市夜景、雪山、人物肖像、火锅、蓝色的车、烟花、森林、猫、毕业典礼、湖、街边小吃。
点击即搜；当前正在搜的 chip 高亮（accent 边框 + accent 文字）。

### S4 结果区
状态行（搜索后出现，一行，等宽小字），必须包含：
查询「<query>」→ 模型实际读到「<translated>」（中文已改写 / 英文原样）· 编码 <x>ms · 全流程 <y>ms · 返回 <n> 张
text_cached 为 true 时追加「· 命中缓存」，并加一行灰色小字：该查询的文本向量已在内存中，编码耗时≈0。
网格：repeat(auto-fill, minmax(170px, 1fr))，gap 12px，≤640px 时 2 列。
卡片：缩略图（按 w/h 比例，object-fit: cover，固定 168px 高）→ 左上角分数 0.292（三位小数，等宽）→ 右上角相对百分比 100% → 底部一行「场景chip · 城市或文件名」截断。
悬浮：边框升到 --line-strong，缩略图 scale(1.02)，160ms。

### S5 能力说明（3 张卡横排，≤900px 竖排）
卡 1 · 这条链路怎么走的：中文 → 短语改写 → 512 维文本向量 → 与 487 条图像向量做点积 → 排序。给一行公式：score = cos(q,k) = q·k / (‖q‖‖k‖)。
卡 2 · 分数为什么长这样：说明 CLIP 余弦的绝对值天然在 0.2–0.35，能比的是相对高低，不是「百分比相似」。这张卡专门用来接住「才 30% 也叫准？」这个质疑。
卡 3 · 全量版在哪：完整系统为 29,712 张照片 / 1,081 段视频 + Immich 原生插件与写回，运行在本地全量环境；本站是 487 张精选样例的轻量演示。

### S6 页脚口径声明（原文保留，不许删改）
> 本页为轻量演示站（2 核 4G），只挂 <count> 张精选样例，用于验证「中文 → 语义检索」这条链路本身；完整图库（29,712 张照片 / 1,081 段视频）、Immich 原生工作流插件、AI 标签写回都在本地全量环境运行。缩略图为 480px WebP（约 15KB/张），一次检索 = 一次矩阵点积。

### S7 详情抽屉（点卡片打开，右侧滑入 420px，≤640px 全屏）
内容顺序：大图（最大 72vh）→ 一行元数据「fileName · 拍摄日期 · 城市」→ 分数块「余弦 0.2917 · 相对 top1 100% · 场景 chip」→ 底部两个按钮：「复制链接」（把 ?q=<query>&pick=<id> 写入剪贴板并 toast 提示）与「关闭」。
右上角关闭；Esc 关闭；抽屉内 ← → 切上一张 / 下一张；点遮罩关闭。

## 6. 交互规格（每条都会被验收）
1. Enter 提交搜索；输入为空不请求，给输入框红边 + 一行提示
2. chip 点击即搜并同步高亮
3. 搜索中显示骨架屏（24 格灰块 + 轻微呼吸），不要转圈 spinner
4. 必须把 translated 展示出来（这是本项目最值钱的一行字）
5. 耗时全部来自响应，不许写「约」「大约」
6. 结果 0 条：显示「没找到符合的照片」+ 三个真实存在的示例词（从 /api/scenes 取 count 最高的三个并配中文名，不许自己编词）+「清空重试」
7. 请求失败：显示 HTTP 状态码 +「后端可能正在重启」+「重试」（重发上一次查询）
8. 超时 10s：用 AbortController 中止并提示
9. 缩略图加载失败：换成 CSS 渐变占位 + 文件名，不留破图图标
10. URL 同步：?q=海边日落 刷新后自动执行该查询；?pick=<id> 自动打开该图详情；用 history.replaceState，不堆积历史
11. 键盘：/ 聚焦搜索框（输入框内除外）；Esc 关抽屉；抽屉内 ← → 切换
12. 演示模式：一个「演示模式」按钮（或按 D），按顺序自动跑 5 个词（海边日落 → 城市夜景 → 火锅 → 蓝色的车 → 人物肖像），每步停留 1.6s，每步在状态行高亮「中文 → 英文 → Top1 分数」，随时可按 Esc 或再点一次停止；不许伪造中途进度条
13. 结果区 aria-live="polite"，每次搜索播报「共 N 张」
14. 移动端：搜索区吸顶、网格 2 列、抽屉全屏、chips 横向可滑
15. 所有按钮 hover / active / disabled 三态齐全，disabled 期间禁止重复提交

## 7. 数据真实红线（违反任何一条即不合格）
- 不许把 score 乘成百分比再叫「匹配度 92%」；只能显示 0.292 三位小数 + 相对 top1 的百分比
- 不许写「准确率 98.5%」「召回率」「准确度提升 3 倍」这类没有出处的指标
- 库藏数量只能写 /api/health 返回的 count，不许自己写 30000 或 29712
- 不许把「中文已改写」藏起来不提，改写是这条链路的真实环节
- 不许把「全量版在本地」这句从页脚删掉

## 8. 性能与无障碍
- 首屏只渲染本次返回的 ≤24 张，绝不预加载 487 张
- img 一律 loading="lazy"、decoding="async"，并带 width/height
- 关键 CSS 内联在 head，非关键样式不阻塞首屏
- 图片 alt 用「场景 + 文件名」，不要空 alt
- 网格 role="list"，卡片 role="listitem"；抽屉 role="dialog" aria-modal="true" 并做焦点捕获
- 移动端 Lighthouse：性能 ≥ 90、可访问性 ≥ 90（跑不了就至少保证无 console 报错、无布局跳动）
