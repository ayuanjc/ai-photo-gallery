# 云影图鉴 · 实时监测面板

> 线上地址：**http://106.52.116.164/monitor/**  ·  静态快照：`/monitor/?snap=1`
> 2026-10-19 部署并实测，运行在腾讯云轻量 2C4G（广州）。

---

## 1. 为什么做

1. **运维需要**：比赛演示站在公网，需要知道 CPU / 内存 / 磁盘 / 带宽 / 服务存活，而不是去控制台刷新。
2. **评分需要**：参赛赛题是「数据智能与可视化」，PPT 副标题写了「可视化」，但 14 页里没有一页可视化内容。这块面板本身就是真实、可点开、可复现的可视化产物，可直接截图进 PPT。

## 2. 架构

```
内核计数器 (/proc, psutil)          ┌─ GET /monitor/          静态单页 (Canvas 绘制)
      │ 每 2 秒采样                  │
      ▼                              ├─ GET /monitor/api/monitor/now      最近一帧
┌──────────────────┐                 │
│ collector (task)│──► deque(900) ──┼─ GET /monitor/api/monitor/history  最近 N 帧
└──────────────────┘   30 分钟环形   │
                                  └─ GET /monitor/api/monitor/stream   SSE 增量推送
                                          │ 新帧才推，一帧 ~0.2–0.5 KB
                                          ▼
                                    浏览器 EventSource → Canvas 折线
```

**关键设计**：
- **一次采集、多方共享**：后台 task 每 2s 采一次进环形缓冲，所有客户端只读缓冲，N 个观众不会让采集成本翻 N 倍。
- **SSE 而非轮询**：一条长连接，2s 推一帧 JSON（~220–460 B）。10 个观众 10 分钟 ≈ 0.3 MB，对 500GB 流量包无感。
- **首屏不空**：页面先拉 `/history?limit=150` 把已采数据画满，再挂 SSE 增量。
- **零前端依赖**：单文件 HTML + 手写 Canvas，无 CDN、无构建，符合「零外网依赖」约束。
- **快照模式** `?snap=1`：只拉一次历史、不建 SSE，用于截图 / 汇报取图（无头浏览器也能截）。

## 3. 面板内容

| 区块 | 指标 |
|---|---|
| 六张卡 | CPU 使用率 / 内存（含 swap）/ 系统盘 / 公网吞吐（入·出·累计）/ 磁盘 IO（读·写·可选温度）/ 检索服务常驻内存与进程数 |
| 四张图 | CPU+内存双线（%）/ 网络吞吐（B/s）/ 磁盘 IO（B/s）/ 系统负载 load1 |
| 状态条 | nginx 与 yunying-demo 的 systemd 状态、磁盘余量 |
| 页眉 | SSE 连接状态（以「最后一次收到帧」判定，不用 onerror 误报）、采样帧数、服务运行时长 |

阈值着色：CPU > 80%、内存 > 85%、磁盘 > 85% 时数值转红。

## 4. 部署

```
/opt/yunying/monitor/monitor.py    5.4 KB   FastAPI + psutil，采集 / SSE / 历史 / 页面
/opt/yunying/monitor/monitor.html 13.4 KB  单页面板（gzip 后 5.4 KB）
/etc/systemd/system/yunying-monitor.service      独立进程，MemoryMax=256M，Restart=always
/etc/nginx/sites-available/yunying              新增 location = /monitor（301）与 location /monitor/
```

systemd 关键项：

```ini
Environment=MON_INTERVAL=2
Environment=MON_HISTORY=900
Environment=MON_SERVICES=nginx,yunying-demo
ExecStart=/opt/yunying/venv/bin/uvicorn monitor:app --app-dir /opt/yunying/monitor --host 127.0.0.1 --port 8101 --workers 1
MemoryMax=256M
```

nginx 关键项（SSE 必须关缓冲，否则不实时）：

```nginx
location = /monitor { return 301 /monitor/; }

location /monitor/ {
    proxy_pass http://127.0.0.1:8101/;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 1h;
    chunked_transfer_encoding on;
    gzip_proxied any;
}
```

> 踩坑：代理响应默认不压缩（`gzip_proxied` 默认 off），页面 13.4 KB 原样传输；加 `gzip_proxied any` 后降到 5.4 KB。SSE 流是 `text/event-stream`，不在 `gzip_types` 里，不会被压缩/缓冲，安全。

## 6. 与云控制台的口径差异（必须知道）

| 指标 | 面板 | 腾讯云控制台 | 说明 |
|---|---|---|---|
| 内存 | 700–735 MB | 403.5 MB | 面板取 `psutil.used`（total − free − buffers − cached），控制台口径更接近 anonymous 内存，不含缓存。**两者都真实，只是分母不同。** |
| 磁盘 | 6.99 GB / 11.9% | 7.1 GB / 11.9% | 百分比一致（控制台按 60GB 标称、面板按 58.94GiB 可用）；GB/GiB 换算差异 |
| CPU | 1–4% | 0.85% | 采样瞬时值 vs 控制台一段均值 |
| 带宽 | 入 0.3–2.4 KB/s、出 1–3.6 KB/s | 0.0003 / 0.00007 Mbps | 同一量级，Mbps 与 KB/s 换算后一致 |

面板页脚已如实标注：「面板显示的是服务器自身口径（与云厂商控制台的计费/取整口径可能不同）；累计吞吐自本服务启动起算，仅供趋势参考，不作为计费依据。」

## 7. 运维命令

```bash
systemctl status yunying-monitor          # 状态
systemctl restart yunying-monitor         # 重启
journalctl -u yunying-monitor -n 50 -f    # 日志（SSE 只在建连时记一条，不刷盘）
systemctl show yunying-monitor -p MemoryCurrent,CPUUsageNSec   # 资源
curl -s localhost:8101/api/monitor/now    # 取一帧
# 改采样间隔 / 窗口：
sed -i 's/MON_INTERVAL=2/MON_INTERVAL=5/' /etc/systemd/system/yunying-monitor.service
systemctl daemon-reload && systemctl restart yunying-monitor
```

## 8. 已知限制（如实说明）

1. **单机视角**：只监测本机，不跨机器；没有 agent 上报机制。
2. **无鉴权**：面板公开可读。只暴露 CPU/内存/磁盘/网络/负载与服务名，**不含**进程命令行、内部 IP、密钥、文件路径。如需收紧，加 nginx `auth_basic` 一行即可。
3. **历史不落盘**：只保留内存中最近 900 帧（30 分钟 @2s），重启即清空。要长期趋势需接 Prometheus / SQLite。
4. **无告警外发**：阈值只在页面上变红，没有钉钉/邮件/webhook 推送。
5. **温度与 swap**：云主机通常读不到 CPU 温度（`sensors_temperatures` 为空，面板自动隐藏该字段）；swap 已开 4 GB 但当前使用 0。
6. **无头浏览器截图不稳**：本机 Edge `--headless --screenshot` 时好时坏（SSE 长连接会拖住 virtual time），取图请用 `?snap=1`。
