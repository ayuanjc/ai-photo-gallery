# 在线演示站 · 活动素材工作流（部署与验收）

> 对象：评委试用入口（第 ④ 项改造）。目标不是「一个能搜图的页面」，而是
> **选活动 → 一句话找图 → 改素材包 → 导出 zip** 三步可走通的成稿链路。
> 本文只写可执行步骤与验收口径，不含推测。

---

## 0. 边界（先记住三条，别的都好办）

1. **不动裸 IP 的 444**。服务器上 `sites-enabled/probe-block` 是 `listen 80 default_server + return 444`（2026-10-25 备案整改结论）。新入口走**子域 + 443**，两个 server 块互不干扰。
2. **演示站零写入**。`yunying-demo.service` 带 `ProtectSystem=strict` + `ReadOnlyPaths=/opt/yunying`，所以 demo 的素材包会话只存在内存（`DEMO_PACKAGE_TTL`，默认 3600s），刷新即失效是设计而非缺陷。真正的写回（归档相册）在主应用，且必须先 propose 再 commit。
3. **台账是数据的边界，不是模型的猜测**。活动名、时段、白名单全部来自 `data/activities/activities.json`；视频/截图中「模型读到的英文短语」那一行照旧保留，两者是并行的证据，不互相替代。

## 2. 部署（本仓库执行，共 5 步）


`.env` / systemd 需要确认的变量：

| 变量 | 演示站取值 | 说明 |
|---|---|---|

## 3. 换校园授权图库（把占位样例换成真素材，6 步）

当前 `data/demo` 是通用样例（雪山大猫之类），台账里每条活动都带 `note="占位素材…"`。换真素材按下面顺序做，**不要先改台账再换图**：

1. **导出素材**：Immich 里按活动建相册 → 导出原图；或直接从 `/opt/yunying/data/thumbs` 对应资产拉取。授权书/知情同意单独归档（比赛材料里要有）。
2. **算图像向量**：走 Immich ML `POST /predict`（`modelName=ViT-B-32__openai`、`entries[].type=image`），逐张取 512 维向量，按导出行序 `np.stack` 存 `embeddings.npy`（float32，行数=图片数）。
3. **写 meta.json**（`data/meta.json`，顶层 `{model, dim, count, items}`，每条字段）：

   | 字段 | 必填 | 示例 / 口径 |
   |---|---|---|
   | `id` | ✓ | Immich asset id（台账里就是它） |
   | `w` / `h` | ✓ | 原始像素宽高（素材包按方向挑图，错一行封面就会选错） |
   | `takenAt` | ✓ | ISO8601 带时区，`2026-09-20T19:10:00.000Z`（台账按它判归属） |
   | `fileName` | ✓ | 原文件名，导出 manifest 用 |
   | `city` / `country` | – | 可空 |
   | `scene_key` / `scene_cn` | – | 场景分类键/中文名，可空（空则理由写「未分类」） |
   | `sub_key` / `sub_cn` | – | 子类，可空 |
   | `scene_sim` | – | 场景置信度，可空 |

4. **生成缩略图**：480px 宽 webp 落 `data/thumbs/{id}.webp`。
   ```python
   from PIL import Image
   from pathlib import Path
   for src in Path("src").glob("*"):
       im = Image.open(src).convert("RGB")
       im.thumbnail((480, 480))
       im.save(Path("data/thumbs") / f"{src.stem}.webp", "WEBP", quality=80)
   ```
5. **生成台账**（脚本已入库，口径写在文件头）：
   ```bash
   python tools/build_activity_ledger.py \
     --activity "act-2026-xinying:迎新晚会:2026-09-01..2026-10-11:迎新晚会|2026 迎新|迎新汇演:校团委:大学生活动中心" \
     --activity "act-2026-biye:毕业合影:2026-06-01..2026-08-31:大合照|毕业合影|毕业照:学院办公室:图书馆前广场" \
     --out data/activities/activities.json
   ```
   口径：按 `takenAt` 落在 `[start, end]` 判定归属；同一张只归一场（按规格顺序先到先得）；时段内没照片的活动跳过而不是生成空活动。
6. **重传并复验**：`bash demo/deploy.sh` → 打开子域 → `GET /api/activities` 的 `count` 与你导出的张数一致 → 随便选一场，搜索结果的 `id` 必须都在该活动白名单里（台账锁范围生效）。

## 5. 主应用侧（同一套能力的完整版）

演示站只做「找图 + 成包 + 导出」，不连接图库。完整链路在主应用：

| 端点 | 作用 | 写库？ |
|---|---|---|
| `GET /api/v1/activities` / `POST /api/v1/activities/resolve` | 台账列表与自然语言/日期解析（多命中返回 `ambiguous`，不猜） | 否 |
| `POST /api/v1/workflow/search-in-activity` | 台账锁范围检索 + 生成素材包（落 `data/packages/{session_id}.json`） | 否 |
| `POST /api/v1/workflow/package/edit` | 池内 replace/drop/add/set_slot（`revision` 冲突即拒） | 否 |
| `POST /api/v1/workflow/package/{session_id}/export` | 导出 zip（manifest.csv + manifest.json + 缩略图） | 否 |
| `POST /api/v1/archive/propose` | 归档提案：算相册名、查重名、统计将新增 | **否（dry-run）** |
| `POST /api/v1/archive/commit` | 确认后才 `get_or_create_album` + 逐资产入册 | 是（可用 admin 回滚） |

只读闸：`COMPETITION_READONLY=true` 时 propose/commit 直接 403（`app/core/readonly.py`），演示期间只留只读行为。

## 7. 评委可能追问的三句（照实答）

- **「为什么不让大模型直接猜活动名？」** 活动名是元数据，不是画面内容。实测「迎新晚会」这类词 CLIP 改写后并不指向特定场次（`translated=False` 原样透传），猜错一次就会把 A 活动的照片放进 B 活动的素材包。台账把这件事变成可审计的字段匹配。
- **「为什么要导出 zip 而不是给一个链接？」** 成稿物是「能直接贴进推文的图 + 每张为什么选它」。zip 里 `manifest.csv` 的 reason 列就是可复核的选图依据。
- **「归档为什么要两步？」** 写回是外部副作用。propose 只算不写（dry-run），commit 才落库，出错可以用 admin 回滚；演示期间整条写链路被 `COMPETITION_READONLY` 关掉。

### 8.4 一个已经踩过的坑（改 demo 的人别再踩）

`app.mount("/", StaticFiles(...))` **必须放在文件最后**。Starlette 按注册顺序匹配，`Mount("/")` 会吞掉之后注册的所有 `/api/*` 路由，症状是前端归档按钮报 `Method Not Allowed`，而 curl 打同一路径却是 200（因为 curl 走 uv（应用）与浏览器无关）——看起来像前端 bug，实际是路由顺序。
