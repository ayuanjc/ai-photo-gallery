# 云影图鉴 · 场景重定位与答辩准备

> 目标：命中赛题「④ 数据智能与可视化 / ⑥ 创意轻应用与互动工具」，把「通用图库搜索工具」重述为「校园场景的影像资产智能体」。
> 红线：所有能力对应已实现接口或已实测数据，不吹指标、不编功能。

## 1. 一句话定位（≤25 字）

**校园影像资产智能体：一句话找到任何一张活动照片。**

- 给谁：社团与院系的影像管理者（学生/负责人/宣传老师）
- 解决什么：数万张活动照片「找不到、归不了档」
- 凭什么：中文语义检索 + 原生写回，2 核 4G 私有部署即可跑

## 2. 三个真实用户故事

### 学生 · 找回自己的高光时刻

- 现在的做法：社团群里喊「谁有去年迎新晚会我在台上的照片」，翻三天群聊相册，靠别人记忆
- 用我们之后：输入「舞台灯光 晚会」，语义检索直接出图；抽屉里看拍摄时间地点确认场次；复制链接发群里
- 支撑接口：`POST /api/search`（中文→短语改写→CLIP 检索）、结果 `takenAt/city/fileName`

### 社团负责人 · 期末交影像资产集

- 现在的做法：从几万张里人肉挑精选、手工打标签分类、压缩打包发老师，一学期一次大工程
- 用我们之后：按场景标签（晚会/比赛/纳新）批量筛选，检索结果一键写回 Immich 相册自动归档；器材与地点统计大屏直接截图进汇报
- 支撑接口：38 场景标签体系、Immich 相册/标签/描述写回（带审计与一键回滚）、`/stats/map|exif|gear` 统计端点

### 宣传老师 · 全院宣传口径统一

- 现在的做法：各社团交上来的素材命名混乱、质量参差，海报配图全靠临时搜网图，版权风险高
- 用我们之后：全院统一素材库，按「毕业典礼」「开学第一课」等场景词秒级取图；素材全部校内拍摄、数据不出校
- 支撑接口：复合条件搜索 `/api/v1/search/multi-condition`（时间+场景+语义组合）、私有部署（无外部 AI API）

## 6. 决赛答辩 8 个刁钻问题及回答

### ① 「这不就是 Immich 套壳吗？」

答：Immich 在架构里只是「存储底座」，相当于数据库。语义链路——中文短语改写、CLIP 文本塔 ONNX 推理、向量检索、动态排序、写回闸门、审计回滚——全部自研（51 个端点、1,085 条测试、36 项审查修复）。且我们零修改 Immich 源码（AGPL 合规），演示站甚至完全不依赖 Immich 也能跑，证明算法链路是独立资产。

### ② 「余弦 0.29 也叫准？」

答：三个事实。第一，CLIP 图文跨模态余弦的典型区间就是 0.2–0.35，0.2917 不是低分（同模型下图文同源对才接近 0.3+）。第二，实测「海边日落」0.2917 的 top1、top2 都是真日落，可现场验证——分数区间和检索效果是两回事，排序靠的是相对差异。第三，我们拒绝乘成「92% 匹配度」的伪口径，展示原始值+全透明过程，这恰恰是可信度。

### ③ 「为什么不用华为云 ModelArts 直接跑？」

答：场景不匹配而非能力不足。我们的模型是现成的 CLIP ViT-B-32 权重，无需训练；校园私有化部署要求「数据不出校 + 断网可用 + 2C4G 低成本」，本机 ONNX CPU 推理（常驻 348MB、命中缓存 0.7ms）是最优解。若未来全校多院系并发上量，ModelArts 推理服务是明确的扩展路径，架构上只换推理后端一处。

### ④ 「487 张样例也太少了吧？」

答：演示站是「算法链路可独立复现」的最小集，不是能力上限。全量环境在本地：29,712 张照片 + 1,081 段视频，检索、写回、插件全链路在跑。样例集有构建脚本（`tools/build_demo_assets2.py`）可参数化扩量；演示页也明确标注了「全量版在本地」，不虚报。

### ⑤ 「中文支持是不是就是接了个翻译 API？」

答：不是。是面向 CLIP 词表的定向短语模板引擎（`a photo of …` 结构 + 最长优先贪心匹配 + 组合），纯本地零外部 API。而且改写是否被采用（`translated_used`）在界面上如实标注——英文直查时我们明示「未改写」，不冒功。

### ⑥ 「照片数据隐私怎么保证？」

答：三层。第一，私有部署，全链路本机 CPU 推理，没有任何外部 AI API 调用；第二，演示站 487 张全部为本队拍摄的照片；第三，Immich 侧数据留在校内服务器，写回走官方 API 且全程审计可回滚。

### ⑦ 「10 个人同时用会怎么样？」

答：如实回答：实测 10 并发不同查询平均 737ms（2 核单 worker，onnxruntime 线程串行是已知瓶颈，写在已知限制里）。演示单用户场景绰绰有余；扩展路径明确：文本塔 int8 量化（406MB→约 100MB）后可开 2–3 个 worker，或升 4 核。

### ⑧ 「比赛完了还维护吗？真有人用吗？」

答：有真实需求窗口——每学期社团纳新季、毕业季、期末交资产集都是高频找图期。落地三步（试点→社团批量→院系统一）以学期为节奏推进，试点期一个社团即可验证。项目自身 1,085 条测试 + 一键部署脚本，维护成本是工程化的低门槛。
